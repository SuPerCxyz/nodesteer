# web-ui/layout Specification

## Purpose
定义 NodeSteer Web 的内容宽度策略、详情页信息结构、Sidebar 密度与前端测试可执行性。本规格只约束前端呈现与测试执行方式，不改变产品功能、API、字段、权限、路由与 i18n 文案。
## Requirements
### Requirement: 统一内容宽度策略
系统 SHALL 让所有页面（列表页与详情页）使用同一内容宽度策略：内容占满可用宽度，最大宽度不超过 2400px；视口可用宽度超过 2400px 时内容水平居中，两侧留白。系统 SHALL NOT 因页面类型（详情/编辑）而在 ≥1280px 时把内容收窄到更小的固定宽度（如 1280px、1600px）。

#### Scenario: 详情页与列表页同宽
- **WHEN** 用户在同一视口下依次打开列表页与对应详情页
- **THEN** 两个页面的主内容区宽度一致（均受同一 2400px 上限约束），详情页不再出现明显更窄的居中列

#### Scenario: 超宽屏居中
- **WHEN** 用户在 3840px 宽的视口打开任意页面
- **THEN** 主内容区宽度为 2400px 且水平居中，表格与卡片不横向拉伸超过 2400px

#### Scenario: 常规视口不受影响
- **WHEN** 视口可用宽度小于 2400px（如 1366/1920）
- **THEN** 主内容区占满可用宽度，不产生额外留白

### Requirement: 详情页单页分区展示
系统 SHALL 将任务、节点、执行详情页的全部信息在同一页面内分区展示，不使用 Tab 切换隐藏信息。每个分区 SHALL 有明确标题，并保持原有数据、操作与链接可用。

#### Scenario: 任务详情单页可见
- **WHEN** 用户打开任务详情页
- **THEN** 概览、定义、目标、执行记录、调度信息均在同一页面按分区可见，无需切换 Tab

#### Scenario: 执行日志功能保留
- **WHEN** 用户在执行详情页查看日志分区
- **THEN** 日志区保持全宽，stdout/stderr/all 筛选、搜索、跟随、换行与复制功能与改动前一致

### Requirement: 详情字段响应式栅格
系统 SHALL 以响应式栅格展示详情字段：窄视口 1 列、≥1024px 2 列、≥1536px 3 列，使字段在宽屏下不显稀疏。

#### Scenario: 宽屏每行多段数据
- **WHEN** 用户在 1920px 或更宽视口打开详情页
- **THEN** 同一分区内每行展示至少 2 段字段数据

### Requirement: Sidebar 短视口完整可见
系统 SHALL 保证在 768px 视口高度、默认展开状态下，Sidebar 的全部菜单项与分组标签完整可见，不被底部账号块遮挡或裁切，且不需要在 Sidebar 内滚动。

#### Scenario: 768px 高度全部可见
- **WHEN** 用户在 768px 高的视口打开已登录页面
- **THEN** Sidebar 显示全部 11 个菜单项与 5 个分组标签，账号块不遮挡任何菜单项

### Requirement: 前端测试可全量执行
系统 SHALL 支持通过 `npm run test` 一次性执行全部前端测试文件并正常结束，不出现文件间挂起；测试结果 SHALL 反映真实用例状态。

#### Scenario: 全量测试正常结束
- **WHEN** 执行 `npm run test`
- **THEN** 全部测试文件被执行并输出汇总结果（通过/失败），进程正常退出
