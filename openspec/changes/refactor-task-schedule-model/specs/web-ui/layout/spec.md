## MODIFIED Requirements

### Requirement: 详情页单页分区展示
系统 SHALL 将任务、调度、执行详情页的全部信息在同一页面内分区展示，不使用 Tab 切换隐藏信息。每个分区 SHALL 有明确标题，并保持原有数据、操作与链接可用。

#### Scenario: 任务详情单页可见
- **WHEN** 用户打开任务详情页
- **THEN** 概览、定义、关联调度、执行记录均在同一页面按分区可见，无需切换 Tab
- **AND** 任务详情不再展示目标节点或执行策略分区

#### Scenario: 执行详情过程与结果分区
- **WHEN** 用户打开执行详情页
- **THEN** 执行过程、执行结果与日志在同一页面按分区可见

#### Scenario: 执行日志功能保留
- **WHEN** 用户在执行详情页查看日志分区
- **THEN** 日志区保持全宽，stdout/stderr/all 筛选、搜索、跟随、换行与复制功能与改动前一致

## ADDED Requirements

### Requirement: Sidebar 命名与三页一致性
系统 SHALL 在 Sidebar 使用「任务定义」「调度计划」「执行记录」，并让三个列表页与详情页使用一致的页面头、工具栏、表格/卡片容器、加载/空态/错误态和筛选控件。

#### Scenario: 三个列表页一致
- **WHEN** 用户依次打开任务定义、调度计划、执行记录列表
- **THEN** 页面标题、搜索/筛选、主操作按钮、表格容器与空态/错误态位置一致
- **AND** 筛选项使用同一套可访问控件，不混用原生 select 与设计系统组件

#### Scenario: 三个详情页一致
- **WHEN** 用户依次打开任务定义、调度计划、执行记录详情
- **THEN** 分区标题、字段栅格、状态徽章、操作按钮与返回入口保持一致

#### Scenario: 短视口可用
- **WHEN** 用户在 768px 高的视口查看 Sidebar
- **THEN** 全部菜单项与分组标签仍完整可见，不因改名产生裁切或遮挡
